# DigiStream UI quality audit

This register tracks concrete UI defects found against current executable code, the approved Echoo references, DigiStream product rules, responsive acceptance and the installed design-agent playbooks. A design suggestion is not a defect unless the current implementation or reference evidence supports it.

Severity:

- **P0** — broken interaction, inaccessible presentation, hidden/unreachable control, overflow or materially misleading state.
- **P1** — confusing hierarchy, inconsistent product flow, excessive task friction or meaningful responsive inefficiency.
- **P2** — visual refinement, cleanup or low-risk polish after P0/P1 issues are controlled.

Verification labels distinguish automated evidence from physical-device or manual visual acceptance. Passing CI alone does not prove every visual condition.

## UIQ-007 responsive audit coverage

The required matrix is **1440×900, 1280×720, 768×1024, 390×844, 360×800 and 844×390**. Each bounded slice records actual defects before correction rather than treating a screenshot or a no-horizontal-overflow assertion as complete responsive acceptance.

- **Slice 1 — Landing, authentication and creator intent:** complete and merged. The exact matrix covers page/internal overflow and primary touch-target size; 844×390 landing columns are bounded instead of clipped, entry controls meet the 44px floor and live landing copy uses Studio Lobby. The change remains in current `main` ancestry and exact-current-main CI is green.
- **Slice 2 — Organisation/channel/broadcast onboarding:** complete and merged. Step 1 keeps truthful Echoo public-slug guidance, the first onboarding heading owns entry focus, automatic first-channel/first-broadcast focus is target-specific to successful step progression, browser Back retains Creator shell focus ownership, and the exact matrix covers long content and 44px controls through the scheduling form. Exact-current-main Node 22/24, responsive Playwright and infrastructure CI are green.
- **Slice 3 — Creator shell, Overview, Broadcasts and Studio:** complete and merged in PR #169. The Creator home brand link and workspace selector meet the 44px interaction floor; Studio diagnostic disclosure controls are at least 44px; the exact matrix uses real authorised multi-workspace, active-channel and draft-broadcast state and verifies shell, Overview, Broadcasts and Studio without claiming LiveKit readiness.
- **Slice 4 — Chat, Studio Lobby and Recordings:** complete and merged in PR #170. Chat history/composer/login controls are normalized to the 44px floor, the legacy pale error foreground is replaced with the semantic danger system, and a dedicated exact-matrix browser test uses real authorised organisation/channel/scheduled-broadcast state to verify Chat selection, Studio Lobby dialog bounds/controls and Recordings state without fabricating media or recording evidence.
- **Slice 5 — Listener discovery/live/request-to-speak/replay:** complete and merged in PR #172 after exact-head CI #777. The responsive ownership layer normalizes remaining discovery/live interaction floors, reduces unnecessary phone and short-landscape visual-stage travel, keeps long listener-facing names wrap-safe, and makes the request-to-speak sheet explicitly contained by the usable short-landscape viewport. The exact matrix covers Discover, live listening presentation, request-to-speak dialog bounds and Replay with long listener-facing metadata.
- **Slice 6 — Guest Join, system states and global overlays/modals:** complete and merged in PR #173. Guest Join now owns a 44px home-brand target, wrap-safe long invitation/session copy and bounded phone/short-landscape density; terminal Session Expired and Not Found states have explicit short-landscape containment. The dedicated exact-matrix browser test uses a real stored guest-session shape while keeping host admission unavailable, and verifies Guest Join plus Session Expired and Not Found without claiming microphone/media readiness. Global overlay containment remains backed by the already-tested Studio, Studio Lobby and request-to-speak production surfaces from slices 3–5. Exact-current-main CI is green.

Existing Android Chrome and Android desktop-site smoke projects remain complementary device-specific evidence; they do not replace the exact matrix above.

## UIQ-008 motion and polish coverage

Motion is accepted only when it communicates interaction or state, stays within the product timing contract, respects reduced motion and does not add continuous decorative work to high-frequency Studio/listening surfaces.

- **Slice 1 — Semantic motion foundation and shared controls:** complete and merged in PR #176. Adds semantic instant/control/surface/overlay/workspace/status tokens within the approved ranges, leaves the existing 120/200/320ms legacy timings unchanged for unaudited selectors, migrates shared Button/IconButton/audio-meter timing ownership, and replaces the reduced-motion slowed shared spinner with a static loading indicator while retaining visible loading text and `aria-busy` ownership. Post-merge `main` workflow #788 is green.
- **Slice 2 — Production overlays, dialogs and disclosures:** complete and merged in PR #178. Final-cascade ownership supersedes legacy `0.01ms` request-to-speak/Studio interpolation under reduced motion, custom dialog controls use semantic control timing, Studio Lobby row feedback no longer animates `box-shadow`, and small touch-device full-screen backdrops drop blur in phone portrait/short landscape without changing overlay geometry or dismissal behavior. No entrance/exit choreography is introduced because these production surfaces unmount synchronously.
- **Slice 3 — Workspace/navigation hierarchy:** complete and merged in PR #178. Creator desktop/mobile navigation and the custom Overview quick action use bounded semantic control feedback for color/background/border changes. No page or workspace-route animation is added, so navigation remains immediate and real application state remains authoritative.
- **Slice 4 — Studio/live high-frequency feedback:** complete and merged in PR #178. Shared, Studio and Guest microphone meters keep stable full-height layout boxes and express level changes with compositor `scaleY()` plus the instant timing token instead of animating `height`; state colors remain truthful and reduced motion removes interpolation without flattening the represented level.
- **Slice 5 — Listener/guest/system-state polish and closure:** complete and merged in PR #178. Listener discovery/status feedback uses semantic surface/status timing, custom listener/guest/system controls receive bounded control feedback, reduced motion stops listener pulse/blink work and the standalone system-state spinner instead of slowing them, and the browser regression checks final computed styles so reduced motion cannot silently regress to nominal-duration animation. Exact-current-main workflow #796 is green across Node 22/24, Playwright and infrastructure/API-image validation.

## Design-skill usage for this programme

- **UI UX Pro Max**: structural UX, responsive hierarchy, accessibility and design-system checks.
- **Impeccable**: broad product-UI critique and final refinement passes.
- **Emil Kowalski `emil-design-eng`**: interaction feedback, component craft and evidence-backed motion decisions after structural correctness.
- **Taste Skill**: only for surfaces within its pinned upstream scope, such as landing/auth-entry presentation. It is not used as authority for dashboards, data tables, Studio or multi-step product UI.

## Non-negotiable truth boundary

No UI correction may invent analytics, listener counts, readiness, lifecycle state, recording/replay availability, permissions, media evidence or success. Existing APIs, authorization, tenant isolation, lifecycle services, current responsible components and approved Echoo references remain authoritative.
